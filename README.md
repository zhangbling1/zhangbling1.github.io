# 张宁 - 个人作品集与后台管理系统

> GitHub Pages 在线展示: [https://zhangbling1.github.io](https://zhangbling1.github.io)

本项目为个人视觉设计与艺术作品集，包含：
- **公开展出端 (`index.html`)**：以“画册”为形式的作品集——纸色底、墨色字、一枚朱红名章；封面、目录、按分类成章、图版编号、深色看图模式、作者页与可打印简历。桌面与手机均可使用。
- **可视化管理后台 (`admin.html`)**：浅色工作室界面，管理全量 1100+ 张素材。支持拖拽、键盘排序、指定位置跨页移动、多选批量操作、撤销/重做、作品编辑、分类管理、简历编辑、本地保存与 GitHub 发布。

### 前端设计说明

首页像一本画册：封面 → 目录 → 各章节 → 封底（联系方式）。每个分类是一章，按 `categories.order` 排列；`visible` 决定是否公开，旧配置中的 `featured` 标记不参与展示。

- **开屏**：首次进入封面时播放约 4 秒的奔马序章。保留 Eadweard Muybridge《The Horse in Motion》（1878，公有领域）的 11 帧轮廓和光流补帧，共 33 个跑姿。成稿阶段对相邻轮廓做有序匹配、时间平滑和连续补间，包含马腿交叉时的内部开口与循环接缝；光影、眼睛与飘带同步采用连续的动作位置，避免上色后逐帧跳动。四个绘制阶段都使用完整步态，依次呈现点描、结构线稿、墨色造型和朱红成稿。成稿以随身体位置变化的柔和光影、肌肉弧线、细密刻线、飘带和马蹄扬尘增加层次，短暂停留后加速化为细小颜料颗粒，纸面淡去、露出封面。排版沿用纸白与朱红，固定套准标记和淡化的参考网格保持画面稳定；底部显示创作阶段与进度，手机与横屏分别适配。点击右上角“跳过”、键盘激活按钮或按 Escape 可立即进入；焦点和页面交互在结束后恢复。动画优先使用 OffscreenCanvas 后台线程，不支持时使用主线程。每个标签页通常只播放一次，从章节锚点进入时跳过；打开 `https://zhangbling1.github.io/?intro` 可重播，系统开启“减少动态效果”时始终跳过。脚本异常有自动解除遮罩的保护。原始帧来源记录见 [jgneff/gif-horses](https://github.com/jgneff/gif-horses)。
- **封面**：右侧是缓慢流动的精选作品（桌面三列、平板两列、手机两行），先取 `siteInfo.workOrder` 里的作品，不足时从各章轮流补足；没有预览图的作品、表情贴纸和极端长图不进入（视频以封面帧出现）。鼠标悬停时暂停并在玻璃卡片上显示作品名，点击进入看图模式；卡片上的按钮可以暂停滚动。
- **液态玻璃**：顶部导航、书眉、按钮、看图模式的控件都是半透明的玻璃质感，边缘高光会跟随鼠标；导航下方的“水滴”会滑到当前页。页面滚动后，顶部三个玻璃按钮下方会淡入一层很浅的纸色渐变，避免和下面的图片混在一起。不支持背景模糊的浏览器会自动改用不透明底色。系统开启“减少动态效果”时，所有动效停用。
- **目录**：每章一张卡片，前面是本章第一幅作品，后面露出接下来两幅作品的颜色，像一叠画；鼠标移到哪张卡片，玻璃底板就滑到哪张。手机上变成带缩略图的列表。封面优先使用预览图；新公开或扫描后的图片没有预览时直接显示原图，预览文件失效时也会回退。视频没有海报时加载原视频的静止首帧；原文件也无法读取时显示明确提示。
- **视频**：图版先显示封面帧和时长，不加载视频；鼠标停留片刻才静音试播，移开即停止下载；点击后在看图模式里带声音播放。视频是 AV1 编码：Chrome、Edge、Firefox 都能播放，Safari 只有较新的设备（iPhone 15 Pro、M3 Mac 及以后）支持，不支持时会显示封面并提示换浏览器。
- **作者页**：桌面端的 6–7 份工作经历排成两行，第一行的最近一份占一半宽度，其余卡片均衡分布。窄屏使用双列或单列，保留完整文字。最近经历由后台第一条决定，新增经历默认放在最前；技能是一排标签；“下载 PDF 简历”使用独立 A4 打印排版，当前六段经历、联系方式和技能完整排入一页，技能标题与标签保持在一起。打印时停用入场动画，避免快速导出时遗漏尚未显示的内容。
- **联系**：封底列出邮箱、微信和电话，各带复制按钮，都来自后台的个人资料。
- **名章**：导航、作者页和封底的红色小方块显示 `siteInfo.brandName` 的第一个字；标语 `heroSubtitle` 在第一个逗号处换行，第二行定时有一道光扫过。
- **作品顺序**：前台与后台共用 `js/portfolio-order.js`。兼容旧配置中的 `workOrder` 优先顺序；在后台移动作品后，该分类改为统一的 `sortOrder`，保存并刷新即可生效，其他分类不变。
- **图版编号**：全书统一编号（从 001 起），同一作品只出现在它所属的章节里（封面图即图版 001）。
- **标题**：有正式标题的作品在图版下显示标题；后台默认生成的“CG风格 #12”这类名字只显示编号。
- **排版**：同一行图片等高、铺满行宽，一般按原始比例完整展示。展示大小同时受原图像素、屏幕像素密度和素材类型限制：普通横图最多 640px 宽，小图、图标和贴纸更紧凑。预览和分批展开均在整行末尾结束；仅在本章全部作品展示完后，最后不足一行的图片保留合适大小，不强行撑满。无预览索引时先使用保守尺寸，图片加载后按原图尺寸更新。在版面里显得过窄的竖图只显示顶部，超宽的全景图居中裁到 2.4:1。真正的长图（宽高比小于 0.5）标注“长图”，在看图模式里可上下滚动看完整。
- **章节预览**：每章默认约 10 幅，手机约 6 幅，并补齐所在行。首次展开到约 30 幅，之后按约 30 幅分批展开，每次自动补齐整行；按钮与底部进度显示实际数量，提供收起及跳到下一类的入口。增加作品后从新增内容继续阅读，收起时保持底部控件的位置。
- **书眉**：滚动到某一章时，顶部导航中间显示当前章节。

所有页面资源和字体均从本站加载。版面优先使用 WebP 预览图（400 / 640 / 1280 三档，按屏幕自动选择），图片到达前先显示该作品的平均色；看图模式先显示预览、再换成高清原文件；预览不存在时回退到原文件。首屏只加载封面上看得见的缩略图，其余在页面加载完成后再取；章节里的图版接近屏幕时才加载。字体是只含拉丁字符的 WOFF2 子集（约 24KB，中文使用系统字体）。新增公开作品后，可运行 `python scripts/build-previews.py` 更新预览和平均色（需要 Pillow），原图不会被改写。视频的封面帧（避开开头和结尾的淡入淡出，挑画面最丰富的一帧）需要额外安装 PyAV：`pip install av`；没装时脚本会保留已有的视频封面，只跳过新视频。

前端为本项目独立实现，没有复制模板代码。Manrope 字体许可位于 `assets/fonts/OFL-Manrope.txt`。

## 快速使用指南

### 1. 启动管理后台进行作品调整（推荐）
在 Windows 电脑上直接双击运行：
```bash
启动管理后台.bat
```
或在终端中运行：
```bash
node scripts/server.js
```
运行后将自动在浏览器中打开后台：[本地工作室](http://127.0.0.1:3000/admin.html)。端口占用时自动递增，以终端显示的地址为准。服务仅监听本机。使用 `node scripts/server.js --no-open` 可关闭自动打开浏览器。

普通静态预览（如 `python -m http.server` 或 GitHub Pages）不具备写盘接口。后台会显示「静态预览」，支持编辑和导出，但不会把下载文件误报为保存成功。

### 2. 在后台调整作品
- **排序**：拖动卡片右上角的手柄，红线表示插入位置；点击序号输入目标位置，可跨页移动或移到最前/最后。手柄获得键盘焦点时，方向键上下移动，Home/End 移到首尾。移动限制在同一分类内，序号包含隐藏作品。
- **多选**：勾选作品或「选中本页」，可以批量移动、公开、隐藏。所选作品在翻页后保留，改变筛选时清空选择；多选移动保留原有相对顺序。可使用紧凑视图或展开全部来整理大型分类。
- **编辑**：点击缩略图或标题，预览原图/视频并修改名称、说明、标签。「分类目录」管理章节名称与顺序；「关于与经历」管理资料、经历及其先后顺序。
- **撤销与保存**：顶部按钮支持撤销/重做（最多 40 步）。Ctrl/Cmd+Z 与 Ctrl/Cmd+Shift+Z 在非输入框中控制操作历史；输入框保留原生文字撤销。Ctrl/Cmd+S 保存。未保存就关闭页面会提示。
- **真实保存**：修改写入 `data/portfolio-data.json`，旧文件自动备份到 `.bak`，临时文件写完后再替换。若磁盘已被其他页面或程序修改，会拒绝覆盖并保留当前草稿，此时可导出草稿再重新载入。
- **素材同步**：「素材同步与发布 → 扫描变化」先列出新增、同名格式替换和缺失记录，确认后才更新配置；保留分类文案、作品元数据与排序，新作品默认隐藏。无法明确对应的改名按新增处理。扫描前需先保存草稿。
- **预览图**：排序和文字修改无需重新生成预览。公开新素材或替换原文件后，单独运行「同步预览图」，等待完成提示。需要 Python 和 Pillow，视频需要 PyAV；可通过 `PORTFOLIO_PYTHON` 指定 Python 可执行文件。

### 3. 发布更新到 GitHub Pages
调整完成后，只需提交并推送到 GitHub 仓库即可生效：
```bash
git add .
git commit -m "Update portfolio showcase"
git push
```
亦可使用「素材同步与发布 → 查看发布清单」核对全部待提交文件和当前分支，再确认提交与推送。使用本机已配置的 Git 凭据，不在网页保存 Token。**本地保存与发布是两个独立操作**，推送完成后仍以 GitHub Pages 的部署结果为准。

## 动画回归检查

运行 `node scripts/check-intro-motion.cjs`，检查成稿阶段在 120 Hz 下是否出现重复姿势，以及全部 33 个姿势（含首尾循环）的轮廓接缝是否连续。此检查直接运行开场绘制代码，不依赖额外 npm 包；视觉效果仍需在 `/?intro` 中复查。

## 后台回归检查

运行 `node scripts/check-admin.cjs`。使用临时目录和本地随机端口验证排序与跨页多选、配置往返、原子保存与备份、冲突拒绝、导入校验、素材扫描保留编辑、同名格式替换和媒体范围请求，不改动真实作品配置，也不调用 GitHub 发布。浏览器还需验证拖拽、撤销、保存后刷新、6/7 份经历两行布局及手机适配。

运行 `node scripts/check-contents.cjs` 验证实际目录渲染逻辑：缺少预览索引、失效缩略图、无海报视频与原文件加载失败。扫描或公开新作品后，即使还没生成预览，目录封面也应正常展示。

运行 `node scripts/check-gallery.cjs` 验证 97 幅作品分批展开、最后一批、收起与手机适配，以及低分辨率横图、图标、落单图片和混合比例图片的尺寸上限与行内边界。

## 目录结构说明
```text
zhangbling1.github.io/
├── index.html            # 前台展出首页 (优化后)
├── index.backup.html     # 原版单文件备份
├── admin.html            # 可视化管理控制台
├── 启动管理后台.bat       # 双击启动本地管理服务
├── css/
│   ├── style.css         # 前台“画册”视觉样式
│   └── admin.css         # 后台浅色工作室样式
├── js/
│   ├── app.js            # 画册结构、图版排版、看图模式与作者页
│   ├── intro.js          # 开屏：Muybridge 奔马（每个标签页只加载一次）
│   ├── portfolio-order.js # 前后台共用排序与配置校验
│   ├── particles.js      # 旧版文件；当前前端不加载
│   └── admin.js          # 后台数据管理、批量操作与保存逻辑
├── data/
│   ├── portfolio-data.json  # 当前生效的作品配置与展出清单
│   ├── media-previews.json  # 可选的预览图索引
│   └── all-assets.json      # 全量素材原始索引
├── assets/               # 本地字体、图标与 WebP 预览图
├── images/               # 素材目录 (CG Style, Cartoon, Character等)
└── scripts/
    ├── scan-assets.js    # 素材扫描与数据初始化脚本
    ├── build-previews.py # 生成公开作品的轻量预览图
    └── server.js         # 本地零依赖管理服务 (提供保存API)
```
